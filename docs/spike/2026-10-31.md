## 四大根因与修复（产品化必须遵守）

### 1. tao 首次 show 重应用 GWL_STYLE → 断父链
tao 在窗口首次 show 时一次性重应用缓存的 GWL_STYLE（overlapped 类窗口 CHILD/POPUP 两位皆无），抹掉 attach 设置的 WS_CHILD 并断掉 SetParent 关系。
**修复**：启动顺序固定为「show → 等 1.5s 样式落定 → attach」（spike_diag5 实测 30s 零断裂）。
**产品落地**：attach 时序必须晚于首次 show ≥1.5s；备选方案（离屏 show 后挂载）留待阶段 2 评估。

### 2. 透明黑块：blur-behind 在 SetParent 后失效
tao 0.37 的透明窗口实现是 `DwmEnableBlurBehindWindow`（全窗口区域模糊透明法，tao window.rs:1204），仅对顶层窗口有效；SetParent 成 WS_CHILD 后 DWM 丢弃模糊效果，GDI 未绘制的重定向缓冲（黑）露出 → S2 初测黑块。
**修复**：attach 时给容器加 `WS_EX_NOREDIRECTIONBITMAP`（EXSTYLE 运行时修改可存活——tao 只重应用 GWL_STYLE）；重建路径同时用 builder `no_redirection_bitmap(true)`（tao 会跳过 blur-behind）。
**产品落地**：所有桌面层窗口一律 NRB（Windows 特化路径），24H2 路径待 VM 验证。

### 3. 0x052C 无条件发送 → 游离 WorkerW 堆积
历次测试无条件发 0x052C 积累 19 个游离 WorkerW 顶层窗口（顶在图标层之上）。
**修复**：`find_wallpaper_workerw` 枚举优先（父==Progman 且无 SHELLDLL_DefView 子窗口），找不到才发 0x052C（1s 超时）后重枚举。

### 4. explorer 死后 Tauri label 永久泄漏 → 重建死锁
宿主销毁连带容器 HWND 销毁后，Tauri 管理器对「外部销毁」的窗口无法释放 label：close() 对已死窗口无效，`container` label 永久占用，重建永远撞「a webview with label `container` already exists」→ S5 初测卡死。
**修复**：每次重建使用唯一 label（`container-r{n}` 递增，当前 label 存 Mutex 全局查询）；build 失败记录错误并带 1s 冷却重试 3 次。
**产品落地**：容器窗口按 `container-{monitor}-{generation}` 命名；已知残留：被外部销毁的旧窗口对象会在管理器泄漏少量资源直至应用退出（tauri 上游问题，阶段 2 评估补丁或提交 issue）。

## 环境事实（本机，验证工具与产品都相关）

1. **显示子系统**：面板原生 1920×1080@125% DPI；原 1536×864 为自定义分辨率，切换后从驱动模式列表消失（120 模式枚举无此项），现以 1920×1080 运行。存在「SIMULATED_1002…」模拟显示设备（AMD）。
2. **explorer 行为**：taskkill /f 后本机**不自动重启** explorer（三次实测均需手动 start）；重启后 Progman 需 30-60s 才创建。注册表热改 AppliedDPI/LogPixels 对 23H2 无效（仅登录时读取）。
3. **截图工具**：PowerShell 5.1 unaware 进程的 CopyFromScreen 在睡眠唤醒后只捕获桌面+topmost 带（普通窗口全部缺失，一度误判「容器不可见」）；**验证脚本必须先 SetProcessDpiAwareness(2)**。.ps1 文件须 ASCII-only（无 BOM UTF-8 被 PS 按 GBK 解析）。
4. **GetParent 噪音**：GetParent 返回 NULL 时 windows crate 报 Err(1460)——陈旧 GetLastError，判断用 `.is_ok_and(|p| p == host)`。

## 内存快照（dev 模式，挂载稳定态）

- spike.exe（Rust 主进程）：73.9MB 工作集（debug 构建 + 控制窗打开；release 预期显著更低，产品预算 25MB 待阶段 5 实测）
- msedgewebview2：15 进程共 1189MB——含另一 Tauri 应用（DSH Desktop）的独立环境树；S5 泄漏残留的已死窗口 webview 会驻留至应用退出
- 单视图渲染进程增量：容器+控制两视图共享浏览器进程，符合 WebView2 共享环境模型

## 决策记录

1. **启动序列固化**：show → 1.5s → attach（根因 1）
2. **透明方案**：blur-behind 弃用，统一 WS_EX_NOREDIRECTIONBITMAP（根因 2）
3. **WorkerW 定位**：枚举优先 + 0x052C 按需（根因 3）
4. **窗口重建策略**：唯一 label + 重试（根因 4）；S5 的 60s/5 次限流保留（25H2 风险缓解）
5. **事件驱动重挂**：TaskbarCreated / WM_SETTINGCHANGE / WM_DISPLAYCHANGE 经隐藏真实窗口消息泵转发，全部实测触发成功
6. **重挂限流**：事件爆发期（DPI 切换）的冗余重挂被 5/min 上限正确节流，看门狗 5s 校验兜底
